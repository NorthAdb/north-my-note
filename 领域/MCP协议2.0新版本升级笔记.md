## 📌 一句话总结

MCP 2.0 相当于把 AI 的"USB 接口"从 2.0 升级到了 3.0：**底层协议做了颠覆性设计，应用层完全向下兼容**，但目前 SDK 封装还没跟上协议的步伐——"脑子跑在了手的前面"。

---

## 📖 什么是 MCP

- **MCP（Model Context Protocol）** 是 Anthropic 推出的通用外设接口类协议，后开源成为 AI 行业标准。
- 类比：就像电脑的 **USB 接口**——电脑不需要知道你插的是什么，插上 U 盘就能读数据，插上鼠标就能点屏幕。
- Claude 也不需要知道你写的是什么工具，只要 MCP 接口对上了，插上来就能跑。
- Anthropic 的初衷：让全世界开发者按照 MCP 规矩写工具，Claude 就能直接连接使用（查天气、看地图、读本地文件、访问公司内网数据库等）。
- 开源后，各大 AI 工具纷纷接入，从"有点私心的产物"变成了 **AI 行业标准**。

---

## 🔥 2.0 核心变动（四大升级）

| 变动方向 | 说明 |
|---------|------|
| **① 从偏向只读到深度读写** | 大幅强化 AI 动手能力，能更稳定地执行长耗时任务，不会因任务太久而卡死 |
| **② 支持多模态传输** | 以前主要传文本，现在协议原生支持图片、音频等复杂数据传输，AI 可看设计图、听本地音频 |
| **③ 多智能体协同** | 支持"插线板/路由器模式"，不同 AI 助手、工具间可互相调用和接力工作 |
| **④ 安全和权限升级** | 引入更细粒度权限控制，可精确规定 AI 只能看 A 文件夹但不能修改，防止误删文件或泄露隐私 |

> [!tip] 类比理解
> 把 MCP 2.0 升级理解为 **USB 2.0 → USB 3.0**：
> - 速度更快、能力更强
> - 老设备依然能用（向下兼容）
> - 新特性需要新设备才能完全发挥

## 👥 对不同群体的影响

| 群体 | 影响 | 行动建议 |
|------|------|---------|
| **普通用户** | ✅ 完全向下兼容，以前用顺手的 MCP 服务照样能用 | 无需操作 |
| **服务开发者** | 需更新官方 SDK 包，小幅修改代码即可解锁新特性 | 更新 SDK + 改代码 |
| **AI 客户端厂商** | 需更新架构适配新功能，相当于给电脑"升级主板"，耗时较长 | 需要时间 |

> [!important] 向下兼容
> MCP 2.0 在应用层面**完全向下兼容**，就像把 USB 2.0 的老 U 盘插在 USB 3.0 的接口上一样能用，只是发挥不出最高速度。

## 🏗️ MCP 服务端核心资源

MCP 服务端经过 SDK 封装后，形态趋同，核心对外暴露 **三类资源**：

### 1. MCP Resource（资源）
- 表示内部资源信息
- 例如：数据库表结构信息
- 通过资源形式对外暴露"我提供哪些信息"

### 2. MCP Prompt（提示词模板）
- 对外提供提问格式要求
- 帮助用户更好地使用该服务
- 例如：查询天气服务的提示词模板

### 3. MCP Tool（工具）⭐ 核心
- 本质就是一个**普通的 Python 函数**
- 函数有说明（告诉大模型这个函数干什么用）
- 中间业务代码想写什么就写什么，MCP 不关心
- 可访问远端服务、查询数据库、读本地文件等

### 对外暴露服务的形式
- **Stream HTTP**：在服务端单独部署机器，启动后暴露一个 HTTP 端口/接口地址，供外部调用

## 🔗 MCP 服务对接流程

```
客户端配置文件 → 引入 MCP 服务 → 重启连接 → 获取资源/提示词/工具 → 使用
```

1. 在支持 MCP 协议的客户端工具（如 Cline）中配置 MCP 服务
2. 所有 MCP 客户端最终都会落地到一个**配置文件**
3. 重新建立连接后，可获取服务端提供的：
   - Resource（资源）
   - Prompt（提示词）
   - Tool（工具）
4. 使用方式：
   - 单独获取提示词/资源来拼装
   - 直接调用工具：给大模型发问题 → 大模型判断需要用哪个工具 → 自动调用并组织参数 → 返回结果

> [!example] 调用示例
> 问"长沙天气怎么样？"
> → 大模型判断使用 Weather 工具
> → 自动组织参数（city=长沙）
> → 调用工具返回"今天下钻石雨"（服务端写的模拟结果）
> → 大模型给出最终回答

## 🔄 新旧版本特性差异

| 特性 | MCP 1.x（老版本） | MCP 2.0（新版本） |
|------|-------------------|-------------------|
| **任务反馈** | 仅同步反馈 | 支持异步任务反馈（长任务执行中可推送中间进度） |
| **Resource 地址** | 仅固定形式 | 支持通过变量/参数定义资源地址 |
| **数据类型** | 仅支持字符串内容 | 支持图片等二进制内容（如 image 形式对外推送） |
| **工具调用** | 仅同步形式 | 支持异步调用 |
| **兼容性** | — | 老版本客户端可连接新版本服务，但无法支持部分新特性 |

> [!warning] 当前限制
> - 老版本客户端能连接新版服务，但**无法读取**新版特有的图片等信息
> - 新版客户端虽能获取图片二进制内容并保存到本地，但部分客户端**尚不支持图片解析**

## 🎬 演示要点

### 演示一：老版本客户端 + 新版本服务端
- 使用 Cline 客户端配置 MCP 服务
- 成功获取资源、提示词、工具
- 调用 Weather 工具返回"长沙今天下钻石雨"
- 异步特性：服务端支持异步推送，但客户端暂不支持接收推送进度
- 图片特性：客户端能获取图片内容但**无法解析**

### 演示二：新版本客户端 + 新版本服务端（SDDL 形式）
- 使用最新 MCP 包构建 SDDL（STDL）形式服务
- 本地启动 MCP 服务 → 客户端连接 → 初始化
- ✅ 成功获取资源列表（如 get web block）
- ✅ 成功获取提示词模板
- ✅ 支持异步调用工具
- ✅ 成功获取图片二进制内容 → 转写保存为本地图片文件（红色方块）
- ⚠️ 底层协议支持异步进度汇报，但 **SDK 尚未提供完整封装**

> [!note] 关键结论
> MCP 2.0 **底层协议设计超前**，但 **SDK 封装尚不完善**，未来会有补充更新。

## 💡 核心结论与启示

> [!quote] 作者观点
> "MCP 2.0 这次升级绝对不是挤牙膏，它真正把 AI 的外设接口带进了 USB 3.0 的时代。"

- **底层协议层面**：做了很多颠覆性设计
- **应用层面**：老老实实，一点点积累、一点点创新
- **当前状态**：脑子跑在了手的前面（协议超前，SDK 待完善）
- **未来展望**：MCP 服务会像 Skill 那样融入各种应用场景，变得更加应用自如

> [!success] 实用建议
> 别盯着还没影的 AI 大饼，**把手头的工具用好，把眼前的业务跑顺，这才是硬道理**。
