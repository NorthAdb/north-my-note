## 背景：为什么本科直接就业

- UP 主**九本**（双非一本）、Java 主语言、在 **TikTok（字节）实习**
- 2025 年 10 月（大二上）绩点卡在保研线边缘，刷到 UP 主「优雅」的就业视频后开始思考出路
- 三条决策依据：
  1. **AI 发展飞速 vs 企业招聘滞后的裂缝**——企业内部已 100% 用 AI 写代码，不存在"通过面试但无法胜任"的问题
  2. AI 浪潮不知何时"关门"，笃定 AI 会深入生活，但形式未知
  3. 开发是**极度吃实践**的领域，读 3 年硕士不划算；3 年后行业不可预测
- 保研擦线 = 弱组 + 无论文进不了算法岗；绩点高没论文也没用
- ⚠️ 判断有前提：路径卡在保研线附近、坚定走开发、是 3 年制硕士

## 第一性原理：学习 = 高效通过面试

- **学习目标 = 就业，就业必要卡点 = 通过面试**
- 一切围绕两件事：**高效通过面试** + **写出一份有辨识度的简历**，而非单纯学习
- "面试造火箭，工作打螺丝"——工作是个人都能做，前提是能进去
- ❌ 误区：黑马网课全看完却后悔——AI 时代"感动自己"没意义
- **包装的艺术**：简历上每句话都不能被问穿 = 知识储备扎实 + 能圆回来
- 没人真的在意你做没做过项目，只要你讲得出：
  - 项目细节、极端情况下的问题
  - 为什么这样选型、为什么这个技术方案
  - 有哪些技术支撑你的改动
- 八股同理：不一定懂每个 API，但被问到的必须流畅回答
- 这不是"邪修抄近道"，是**聪明的学习 / 有取舍的学习**

## 标准简历 & 标准面试

### 简历的四个板块
- **教育背景**（已定，除非读研）、**实习经历**（可刷）、**项目经历**、**技能优势**
- 可改变项按含金量排序：**学历 ≈ 大厂实习 ≈ ACM 金牌**（最有辨识度）
- 水赛警告：大创、挑战杯、数模对计算机无含金量

### 标准面试流程
1. 自我介绍 1–2 分钟
2. 聊实习经历
3. 聊项目（重点）
4. 结合项目拷打基础（八股）
5. 场景题/智力题（面试官常拿自己最近在做的业务考思路）
6. 算法题（1–2 道）
7. 反问（2–3 个问题）

> 若面试官不聊项目、上来直接库库背八股 → 大概率没看上你，在耗时间。

## 后端学习路径（核心，六步）

### 第一步：成为 AI 时代的原住民 ⭐
1. **魔法上网**——接触最前沿信息
2. **注册 GitHub**——最前沿项目 + 所有资料
3. 配置并深度使用 AI：Codex / Claude Code / ChatGPT / Gemini
   - Claude Code 最好用，但国内用不了；**当前最优解：Codex**（经常重置额度，性价比高）
4. 学习 **Vibe Coding**（自然语言对话编程）与 **Spec Coding**（规范编程，用技术/产品文档驱动，减少 AI 幻觉）
5. **建立信息收集渠道，打破信息差**（标红重点）——机器人/牛客/小红书/B站博主/同伴，别一个人闷头敲代码

### 第二步：选语言（后端只有 Go 和 Java 两种）
| 维度 | Go | Java |
|------|----|----|
| 定位 | 高并发原生语言，大厂标配，迅速扩张 | 中国存量最大（~80% 岗位），百搭 |
| 八股量 | 约 Java 的 1/5 | 特别多 |
| 竞争 | 较小 | 激烈、培训规模化 |

**推荐先学 Java**：
- 存量最大、有退路
- Go 的岗位接受 Java 转（进字节后从 Java 转 Go 很正常）；Java 的岗位不接受 Go 转

### 第三步：技术栈（按学习顺序）
1. **408 计算机四大件**：数据结构 → 计算机网络 → 操作系统 → 组成原理
   - 字节/腾讯最爱考察基础；组成原理考察相对少
   - **不建议一上来就啃**，至少学完 Java 再来，否则严重摧残自信心
   - 学习理念：先**广泛铺开、快速闪击**，别死磕一个点——学到后面（如 MySQL）前面问题自然迎刃而解
2. **语言三件套**：Java SE → JUC（并发）→ JVM（底层）
   - 理解为主、拒绝背诵；语言是根基，但别陷进语言泥潭
3. **数据库**：MySQL + Redis（面试必考，每场后端面试必有）
   - MySQL 可替换为 **PostgreSQL**（AI 时代优势：原生向量检索、开源、更新快；MySQL 闭源后更新慢）
4. **框架**：JavaWeb / Spring Boot / MyBatis-Plus（面试考察少，边做项目边学）
5. **工程工具**：Git / Linux / Docker（工作必备，动手实操为主）
6. **中间件**：ES + RocketMQ（可换 Kafka / RabbitMQ，三选一）——**面试拷打重灾区**

### 第四步：算法
- 面试必考，一般难度 **mid**；字节爱出 hard（还是 Hot100 之外的 hard）
- 刷题模式：核心代码模式 vs ACM 模式
- 新题写不出来很正常——除非刷到一两千题有了举一反三能力；算法**运气成分大**（面试官想不想为难你）
- 题单选择：
  - 时间充足 → 找完整题单按模块刷（从母题延伸，循序渐进）
  - 时间紧 → **Hot100 + CodeTop** 针对性刷（覆盖面试 70–80% 原题）
  - hard 性价比低，刷 mid/easy 为主
- **三三遍刷题法**：
  1. 第一遍：每道题 3 分钟没思路直接看题解（别死磕），目的是建立印象、找能理解的题解
  2. 第二遍：回顾昨天的题，建立框架往里填代码，忘记的细节思考为什么忘
  3. 第三遍：独立想起注意事项并 AC
- **什么时候开始**：选完语言就开刷（与其它内容解耦）；核心是**集中大量 + 养成习惯**（每天上午固定算法时间，一次做几道到十几道）
- 熟练标准：看一眼题目马上有思路、能默写，100 道题 1–2 天过一遍

### 第五步：项目
- 时机：**学完数据库 → 学完工程工具 → 开始做项目**（边做项目边学技术栈，用到什么学什么）
- 项目 = 完整可落地的作品；但"图书管理系统"这类太 low 不能上简历
- 核心观点：**实现框架原有能力 ≠ 亮点；做出完整系统 ≠ 亮点；在此基础上的优化 = 亮点**
- 技术栈不是堆叠报菜名——必须能讲出**选型必要性**，讲不出就是浪费
- 项目考察的是：架构设计能力、问题处理能力、八股理解能力（八股常结合项目场景问）
- ⚠️ 避雷：**外卖/点评/秒杀类烂大街项目**（1000 份简历 800 份是这个，面试官一眼识破）
- 推荐配置：**传统后端项目 + AI Engine 项目**；有实习可只留一个项目，无实习至少两个
- 好项目的四个标准：
  1. 围绕**用户痛点**（不是凭空捏造）
  2. **完整性**：文档、测试样例、压测
  3. **闪光点**：如何解决难点（模板：某场景下出现什么问题 → 对比方案 → 采用什么方案 → 解决什么问题 → 最终优化了什么）
  4. **可沉淀性**：内容能沉淀成 Skill

### 第六步：八股
- 八股 = 面试官对技术栈的提问（因回答死板而得名），但实际有很多灵活表达拉开差距的地方，工作后也用得上
- 时机：**快面试时再背**；激进做法：直接通过背八股学技术栈（邪修，但底层理解会少一些）
- 方法：**理解为主，背诵为辅**；多刷面经找高频考点；善用飞书记录思考/没答上的题/灵光乍现
- 拿来主义：直接用人整理好的，不必自己整理
