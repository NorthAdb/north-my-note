## 一句话总论

> **teach 是一个「有状态」的 skill——把 AI agent 变成懂你学习进度的私人老师。** 它会在当前目录建起一整套教学工作区（mission / resources / 可交互 HTML 课程 / glossary / 学习记录），核心教学理念是**最近发展区**：每节课都精准落在「正好被挑战到、但不至于被吓退」的区间里。

## 有状态 vs 无状态 Skill

| 维度  | 无状态 skill               | 有状态 skill                                   |
| :-- | :---------------------- | :------------------------------------------ |
| 记忆  | 不保留上次运行状态               | 记住你学到哪了、掌握了什么                               |
| 存储  | 不在文件系统保存东西              | 存本地文件系统或 MCP servers，留下笔记追踪                 |
| 例子  | **grill-me**（不断考你直到能上手） | **grill-with-docs**（保存 ADR + 术语表）、**teach** |
| 适用  | 一次性、无连续性的任务             | 需要跨会话推进的学习/项目                               |

> Matt 的关键判断：他所有好的教学都是有状态的——老师记得你学到哪了、知道下一步学什么、记得积累的好资源。所以 teach 必须是**有状态**的。

> 设计 skill 时，要仔细想清楚它到底该无状态还是有状态——两者没有谁更好，只是适用场景不同。

## 教学工作区结构

运行 `/teach` 后，在当前目录建起一整套结构：

| 组件 | 作用 |
|:----|:-----|
| **mission.md** | 学习目标——老师先理解「你**为什么**想学这个」，把目标写下来 |
| **resources/** | 高可信一手资料（网上搜索，第一次教时创建，随进度持续更新） |
| **lessons/** | 编号的独立 HTML 课程文件 |
| **glossary/** | 术语表——学到的一切行话都进这里，后续课程可引用 |
| **速查表 / 还原卡** | 一页看完全过程（如魔方还原卡） |
| **learning records** | 学习记录——汇报进度时 agent 创建，追踪进度 |
| **notes.md** | agent 内部笔记（你的偏好、注意事项） |

## 为什么课程用 HTML 而不是 Markdown

**HTML 比 Markdown 丰富得多**，这让学习体验出色：

- 内容更有表现力、更有交互性
- 图解、提示框、测验
- **可点击的交互**（演示中魔方教程给出可点的交互式算法演示，带引导模式可开关）
- 拥有整个浏览器的能力

## 核心教学理念：最近发展区

> **最近发展区（ZPD）**：始终在一个人「正好被挑战到、但不至于被吓退」的区间里教他。

- 每节课必须**简洁、紧凑**，精准落在最近发展区
- 学生既不会无聊（太简单），也不会慌乱（太难）
- 随着学习推进，agent 根据你的进度**量身定做**下一节课

**教学三层模型**（Matt 希望 skill 用的思考框架）：
1. **知识**：用高质量、高可信的资源给
2. **技能**：用高度相关、可交互的课程培养
3. **智慧**：用与其他学习者和实践者互动获得——课程底部会找能提问的社区

> 关键：当你提出「需要智慧的问题」时，agent 的默认姿态是**先尝试回答，但最终交给社区**。

## 实战演示：还原魔方

- **mission**：Matt 想能拿起打乱的三阶魔方至少独立还原一次（目标=成就本身，不是速度/理论）
- **第一课**：结构、记号与白色十字——只教当下需要知道的，配图解/提示框/测验
- **进度追踪**：完成一节课说「我能做出白色十字」，agent 记录到学习记录，定制下一节课
- **角循环课**：Matt 说「我已经基本能还原了，除了角循环」→ agent 检查工作区状态 → 诊断「概念已掌握但没形成肌肉记忆」→ 生成专门的角循环课（四步口诀重复两遍 + 可点击交互）

## 工程价值：onboard 新人到代码库

Matt 认为 teach 在 onboarding 场景特别有用：
- 写文档是苦差事：难维护，而且文档很可能不在读者的最近发展区（要么熟悉技术栈但不懂业务领域，要么反之）
- 用 teach：把新人领进工作区、指向代码库 → 他们能独立学会怎么和代码打交道
- **结果：在创纪录的时间里拥有一个能干活的员工**

---

## 更大的愿景：开发者是 AI 先行者

Matt 的思考：
- 开发者社区是**第一批在 AI 极擅长的事情上（写代码）亲身体验 AI**的人
- 我们是世界上第一批真正了解 AI、打造这些酷东西的人——这个新空间的先行者
- 可以把在编程领域积累的经验变成 skill，**带到更广阔的世界**
- 当你在 Claude Code/Codex 里觉得吃力时，想想：未来能把现在练就的与 AI 协作的直觉，带到编程之外的领域
