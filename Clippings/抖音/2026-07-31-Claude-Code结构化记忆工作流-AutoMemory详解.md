## 一句话总论

> **Compact 不是记忆，Handover 不是记忆，CLAUDE.md 也不是记事本。** 大部分人把「上下文管理」当成了「长期记忆」——这是 Claude Code 使用中最经典的错误。真正的长期记忆是 **AutoMemory**：文件式结构、索引常驻、细节按需加载，配合四段提示词实现跨对话持久化。

---

## 核心误区：为什么你的操作是错的

### ❌ 误区一：用 Compact 续命

**你做的**：上下文快满时点橙色圆圈让 Claude 压缩（Compact）

**实际发生了什么**：Compact 的目标是**让当前对话继续放得下**，不是让对话永久存活。反复 Compact 会导致早期信息经历一轮又一轮的重新概括——就像表情包被反复截图转发，越来越糊，细节越来越少，直到早期关键信息在概括中悄无声息地消失。

> 后果：模型不只是忘了，它连自己忘了这件事也忘了——它会「错误否定」，把摘要里没保留的误判成原文里从来就没有过。

### ❌ 误区二：用 Handover 接力

**你做的**：换新对话时让 Agent 把当前进度写成 Handover 交给下一个对话

**实际发生了什么**：每一份 Handover 都在丢失细节。一份有 10 个细节，第二份剩 8 个，第三份剩 6 个，到第 10 份早期细节基本消失。

### ❌ 误区三：把 CLAUDE.md 当临时记事本

**你做的**：把排查记录、临时方案、Bug 进度填进 CLAUDE.md

**实际发生了什么**：CLAUDE.md 是项目指令文件——应该放长期稳定、每个对话都需要遵守的内容（项目背景、技术栈、编码规范、目录约定）。Compact 后 CLAUDE.md 仍会重新加载，如果什么都往里面塞——你说一句「你好」，Claude 得先读完几千行陈年烂谷子。

> 类比：相当于用了一剂「无量空处」，5 token 的请求需要先处理几千行无效信息。

## AutoMemory 是什么

2026 年 2 月，Claude Code 加入了 **AutoMemory**（自动记忆库）功能，默认开启。

| 特性 | 说明 |
|:----|:------|
| **存储结构** | 文件式结构，每个项目独立记忆库，默认在用户目录 |
| **主索引** | `MEMORY.md` 常驻上下文，告知模型当前记忆文件 + 一句话概括内容 |
| **子文件** | 细节写在子文件中，默认不加载 |
| **加载策略** | 新对话加载 MEMORY.md 前 200 行 / 前 25KB（先到者为准）。模型判断需要时主动调取子文件 → **索引常驻，细节按需加载** |
| **四种标签** | **Preference**（偏好）、**Style**（配合方式/经验）、**Project**（状态/决策）、**Reference**（资料/路径） |

## 四段提示词工作流

### 第一步：检查与初始化

给模型一段提示词，让它：
- 检查 AutoMemory 是否已开启
- 建立五个写习惯：一文件一主题、写入前查重、新结论覆盖旧结论、已有内容不重复、只存「对将来有价值」信息
- 可选：对话记录保留期从 30 天改为 365 天（甚至 3650 天），防止漏记时能回溯

### 第二步：日常跨对话衔接（核心）

**时机**：长期任务完成阶段 / 出现橙色圆圈时

**正确做法**：
1. ❌ 不要点圆圈压缩
2. ✅ 给提示词 → 把阶段结论写入记忆库
3. ✅ 打开新对话 → 给提示词 → 自动读取记忆库

> 新对话拥有干净上下文 + 经过整理的长期记忆，不需要继承前一对话的噪声

### 第三步：定期维护

让 Agent 检查：有没有重复记录、过时结论、需合并条目、MEMORY.md 是否接近 200 行/25KB

### 四段提示词一览

| 时机 | 用途 |
|:----|:------|
| 初始化时 | 检查状态 + 建立习惯 + 延长保留期 |
| 旧对话结束时 | 整理写入记忆库 |
| 新对话开始时 | 读取继承上下文 |
| 使用一段时间后 | 清理维护 |

## 四条核心经验

### ① 非必要不压缩

压缩有三种方式，前两种不要用，第三种**偶尔**可用：
1. 满了自动压缩 ❌
2. 主动点击橙色圆圈 ❌
3. **带目标的 `/compact`** ⚠️ — 手动指定保留目标后压缩。仍会丢细节，区别只是你告诉模型优先级

### ② 分层保存

| 层级 | 内容 | 存放位置 |
|:----|:-----|:--------|
| 第一层 | 确定性控制（禁止合并、只允许某些命令） | **Settings / Hooks** |
| 第二层 | 每个对话都应遵守的指导原则 | **CLAUDE.md**（保持精简） |
| 第三层 | 需实时查阅的事实和经验 | **AutoMemory** |

### ③ 用 Obsidian 查看记忆库

记忆库全是 Markdown 文件，用双链相互引用。**把 Obsidian 直接开在 Memory 文件夹上**，打开就是项目记忆图谱。偶尔翻一翻，看看 Agent 记了什么，记错的当场揪出来改。

### ④ 不写敏感信息

密码、API Key、密钥不要写进 AutoMemory。必须留线索时只记「由哪个系统管理」或「从哪个环境变量读取」。

## 对比测试：Compact vs AutoMemory

### 实验设计

- **材料**：老舍《茶馆》全文 33,414 字符 → 切成 8000 字左右的四段
- **模型**：Claude Sonnet 5，相同参数
- **A 组（Compact）**：同一个对话，每段后 Compact 一次，四次
- **B 组（AutoMemory）**：每段后写入记忆库，新对话读下一段
- **约束**：B 组全部记忆 ≤ 4000 字符
- **抗干扰**：做了人名/地名替换，答出原名即作废

### 结果

| 维度 | A 组（Compact） | B 组（AutoMemory） |
|:----|:--------------:|:-----------------:|
| **得分（13 题）** | **5 分** | **8.5 分** |
| 总字数 | 8,644 字符 | 3,677 字符（≤4000） |
| 常驻主索引 | — | 仅 326 字符 |

### 最关键的发现

**A 组（Compact）** 答错的 5 道题全集中在**最后一段材料**，前面三段全错。其中第 7 题问某位第一幕大量出现的人物——A 组不是回答「不记得」，而是**非常确定地说「文本中没有出现这个人物」**。

> 她把当前摘要里没保留的，误判成了原文里**从来就没有**。不只是忘了，她连自己忘了这件事也忘了。

**B 组（AutoMemory）** 同样有不会的题，但回答是「我的记忆记录了松二爷养鸟，没有记录是什么鸟」——虽然没有得分，但暴露了关键区别：她能区分**「笔记没记录」**和**「原文里从来没有」**。

### 结论

> 结构化记忆忘得更可见、记得更可维护。反复 Compact 则出现早期信息衰减 + 典型的错误否定。

## Engramory 协议

UP 主开源的记忆整理协议，核心三部分：

1. **明确四类记忆**（Preference/Style/Project/Reference）的用途和写入标准
2. **去重机制**：写入前查重，能更新就不新增，发现错误就修正，已有内容不重复
3. **有上限的索引**：接近容量时主动提醒，超限时拦截

**时间线**：
- 6/13：UP 主提交索引容量管理设计
- 6/22：Claude Code 加入索引接近上限提醒
- 7/14：官方把超限写入改为显示报错（而非无声失败）
