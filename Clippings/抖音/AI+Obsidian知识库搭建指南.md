> 两个视频的核心共识：**AI 可以参与思考，但不能替你理解；AI 负责整理执行，人负责判断决策。**

## 🎯 视频1：如何用 AI + Obsidian 搭不吃灰的知识库

### 核心洞察

> "我用 AI 搭的第二大脑很快就吃灰了，因为里面的笔记不是我写的，线也不是我连的。虽然整个系统看起来很完整，但我并没有真的理解它。"

- **错误做法**：让 AI 一键生成所有笔记和知识网络 → 看起来完整，实际与自己无关
- **正确定位**：AI 可以参与思考，但**不能替你理解**
- **关键原则**：把信息处理的**主导权拿回来**，人负责最后下判断和做决定

### 四步工作流

#### 1️⃣ 信息输入（轻松）

- 让 AI 帮你找到相关的**一手资料**
- 用 **WebClipper** 把材料直接保存到 Obsidian
- 默认保存位置设为 `01-raw` 文件夹 → 负责存档，收藏不等于学习

#### 2️⃣ 信息处理（费脑子，人主导）

分两步走，**先自己思考，再让 AI 介入**：

**第一步：Source Notes（随手记）**
- 为每本书/每篇材料单独新建一条笔记
- 一边读一边随手记下自己的想法
- **没有 AI，没有要求和限制**，想到什么记什么
- 目的：保留一段属于自己的思考过程

**第二步：Wiki Notes（整理成永久笔记）**
- 让 AI 读取你写的随手记，找出**长期值得保留**的观点
- AI 生成一条条独立的笔记
- 可以问 AI："按照卡片笔记法原则，这条笔记还有什么值得改进的？"
- **人逐条审核**（像批奏折一样），只有认同且理解后，才让 AI 写入 `wiki notes` 文件夹

> 💡 卡片笔记法原则：写笔记时要考虑**未来的自己**会怎么使用它。哪怕一年后完全忘记了原书，再次看到这条笔记仍能理解其中的观点。

#### 3️⃣ 建立链接（知识网络化）

- 每完成一轮新笔记，问 AI："这些笔记之间有什么关联？"
- AI 提供链接建议，**人逐条确认**
- 确认后 AI 把链接更新到笔记中
- 高质量笔记 + 链接 → 形成自己的知识网络
- 网络图负责展示关系，主题积累多了可让 AI 整理**目录页（MOC）**

> 🔄 **持续维护**：每隔一段时间让 AI 重新检查知识库，看有没有遗漏的链接或需要更新的内容。

#### 4️⃣ 输出（从知识库到作品）

- 经过前面的环节，写文章/做视频不用再从零开始
- 很多观点直接来自之前积累的笔记
- **写作不是 make plans，而是 become expert**
- 用自己的话重新表达信息 = 理解过程
- 成熟状态：能够独立做判断和决策

### 金句与比喻

- > "这就像我 1 分钟健身房都不想去，但幻想有个机器可以让我躺进去就长肌肉。"
- > "有点麻烦不一定是坏事，它会让你变得更挑剔，去想这条笔记是不是真的有必要记下来。"
- **拍立得比喻**：因为每张相纸都很贵，所以每张照片都拍得很认真；用手机则会留下几千张再也不会打开的照片。

## 🚀 视频2：Obsidian 联动 Codex 打造"自迭代"生长知识库 2.0

### 核心理念

- **Obsidian** 负责管理知识（本质是 Markdown 文件，Codex 可直接读写）
- **Codex** 负责统筹、维护知识库
- **你**只负责提出需求、挑出重点、做决定
- 剩下的整理、归类、更新全部交给 AI

> 知识库不只是收藏夹，而是升级为一个**知识管理员**。

### 理论基础：Karpathy 的 LLM Wiki 三层架构

| 层级 | 用途 |
|------|------|
| `raw` | 存放原始资料 |
| `wiki` | 存放整理好的、能看的文档 |
| `agents.md` | 存放给 AI 能看懂的说明书 |

**与普通知识库的区别**：不是"你问它答"的高级搜索框，而是把每一次搜索、阅读、思考、整理**重新沉淀回 wiki**。下次使用时，AI 能站在已有知识基础上再前进，而不是每次重新思考。

### 六大目录结构

在三层架构基础上拆出 6 个目录：

| 目录 | 存放内容 |
|------|----------|
| **项目** | 现在正在做或最近打算做的事 |
| **资产** | 已处理好的知识（往期脚本、定稿报告） |
| **资料** | 外界收集的资料（参考资料、公开数据） |
| **归纳** | 暂时结束但仍会回看的项目和资料 |
| **灵感库** | 随时冒出来的标题、案例、内容碎片 |
| **skill** | 固化下来的工作方法，让 AI 以后可直接调用 |

> 清晰的目录区分 = 减少资料乱堆 + AI 也知道每份资料该去哪归档、从哪调用。

### 三阶段使用法

#### 1️⃣ 信息收集

**方式一：Codex 主动联网搜索**
- 给 Codex 一个研究目标（如"1 小时内快速了解 AI 芯片存储行业"）
- Codex 联网搜索靠谱资料，自动填入知识库
- 建立阅读路线、研究框架、产业链地图、核心玩家情况
- 不是一份做完就结束的报告，而是**可持续更新的行业认知系统**

**方式二：手动随手收集**
- 用 WebClipper 插件，网页中选中重要内容直接保存为 Markdown 笔记
- 部分视频页面可直接提取字幕，做笔记后一键存入
- 其他平台的分散资料可用插件批量导入

> 适用场景：行业研究、学习、个人规划、公司变化、客户动态、竞品信息、岗位资讯——凡是大量分散、持续更新、反复调用的信息都可以扔进去。

#### 2️⃣ 信息管理与迭代

**知识迭代系统（输入-消化-输出闭环）**
- Codex 基于已有结构定制迭代系统
- 每次新内容输入，Codex 自动判断：重复？过时？值不值得整理成模板？
- 学生用来整理学习笔记，打工人用来管理项目案例，创作者整理素材选题

**定时自动化任务**
- **每日知识蒸馏**：设定时间（如下午 5 点），Codex 自动整理当天所有工作，生成总结文档存入对应文件夹，关联相关文档链接
- **每周会议纪要/重要信息**：设定定期任务，相当于自动完成周报
- **知识体检**：定期让 Codex 检查目录是否混乱、资料是否重复、哪里缺东西，列出问题和优化建议，可直接修改或变成待办

#### 3️⃣ 信息输出

- 调用已固化的 **skill**（工作方法模板），一句话生成报告
- 结合 API 和数据库生成配图、动画效果
- 调用插件一句话直出 PPT，风格统一、内容详实，可直接下载编辑
- 甚至把文章直接转成视频摘要（简洁大气风格 + 高级动画）
- 生成的产物继续存回知识库，成为下一次分析的基础

### 六字诀

| 口诀 | 含义 |
|------|------|
| **随手收** | 平时刷到有用的视频、文章、观点，直接丢进知识库或让 Codex 帮总结归档 |
| **自动收** | 设置自动化（如每天早 8 点自动搜集最新 AI 资讯，整理成摘要存入指定目录） |
| **定期收** | 每周让 Codex 检查整体知识库，看哪些内容混乱、哪些需要更新，人只需要点头 yes 摇头 no |

### 最后提醒

> "AI 能帮你思考，但是它代替不了你行动。它可以五分钟之内帮你生成方案、规划产品、设计项目，但是它不会替你开会、拍板、背锅。真正让这些方案落地的人还得是你。"

- 别一开始就追求完美，先搭建起来
- 只要它帮你省下从零开始的时间，那就很值了

## 🔗 两个视频的对比与整合

### 相同点

1. **人是最终决策者**：两个视频都强调人负责判断和决策，AI 负责执行
2. **知识库要持续维护**：不是建完就结束，而是不断迭代更新
3. **链接的重要性**：新知识必须与已有知识建立联系，才算真正进入知识系统
4. **输出导向**：知识库的最终目的是为了输出（写作、报告、视频等）

### 不同点

| 维度 | 视频1（Remy） | 视频2（智选） |
|------|--------------|--------------|
| **人的参与度** | 高，全程参与思考和审核 | 中，主要做决策，AI 自动执行更多 |
| **AI 自动化程度** | 低，AI 只做辅助整理 | 高，AI 可定时自动搜索、整理、体检 |
| **核心关注点** | 深度理解、防止吃灰 | 效率提升、自生长迭代 |
| **目录结构** | 简单（raw / source notes / wiki notes） | 复杂（6 大目录 + skill 体系） |
| **适合人群** | 学习者、读者、深度思考者 | 职场人、研究者、内容创作者 |

### 整合建议

- **学习/读书场景**：采用视频1的方法，先自己写 source notes，再让 AI 整理成 wiki notes，确保深度理解
- **工作/研究场景**：采用视频2的方法，用 Codex 自动搜索整理 + 定时任务维护，提升效率
- **两者结合**：用视频2的目录结构和自动化做基础设施，用视频1的"先思考后 AI"原则处理核心知识，既高效又不丢理解
