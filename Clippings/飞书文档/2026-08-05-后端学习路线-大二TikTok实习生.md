## 一句话总结

> 一个「**第一性原理**」驱动的就业型学习路线：目标不是学知识，而是**通过面试**——用简历包装（面试深挖项目细节）+ 八股（理解式背诵）+ 算法（刷题节奏）三个杠杆，把 6 个月左右的学习投入最大化地转化为 offer。核心观点：**AI 时代，古法学习（把所有知识点弄懂）除了感动自己没有意义，要聪明的学、有所取舍的学。**

## 一、为什么选择本科就业

作者 25 年 10 月大二上学期，均分卡在保研线附近，看完 UP 主【优雅】的就业视频后开始思考，最终决定本科就业：

1. **行业裂缝**：处于 AI 发展飞速与企业招聘滞后的裂缝，AI 浪潮不知道何时"关门"；开发极度吃实践吃经验，AI 彻底重塑工作流。坚定走开发的读三年硕士不划算，三年后行业如何不得而知。
2. **保研不划算**：即使擦线保研也是弱组，没有论文进不了算法岗；差 0.01 分和差 60 分没有区别。就业提前规划就能拿到不错结果，没必要为保研冒险走把握更大、失败概率更小的路。

## 二、哪些人不适合本科就业

1. 没有充分的自驱力和决心，自学能力差
2. 想去垄断性央国企总部 or 省分
3. 想去做算法（搜广推、LLM、agent）、AI infra 训练、算子
4. 想去阿里云（"本科生最严厉的父亲"）

## 三、聊聊大厂（优缺点）

**优点：**
1. 薪资可观：校招普遍是央国企两倍，五年内差距扩大到四五倍
2. 福利好：体面的环境、零食饮料、北上广深繁华地段
3. 人才密度大、平均年龄小、成长快、相对不吃背景、官僚作风少
4. 不满意可跳槽，保留差异化能力选择更多

**缺点：**
1. 强度大、加班常态：单位时间工作强度大，同时做两三件事是常态，磨洋工/能力跟不上/成长不达预期都会被淘汰
2. 不稳定：三十五岁危机提前到三十岁危机，更多人因太累主动离职，选大厂基本告别安逸
3. 行业未来无法预知：AI 迅速改变格局、颠覆工作方式，只能拥抱变化

## 四、第一性原理（核心方法论）

> 你学习的目标是就业，进入企业的必经卡点是面试。**所以所做的任何事情都围绕着：①高效地通过面试 ②写出一份有辨识度的简历，迅速进入实习阶段，而非单纯学习。**

- "面试造火箭，工作打螺丝"——工作谁都能做，前提是你能进去
- 古法学习派（每个知识点弄懂、几百集黑马网课看完）在 AI 时代**除了感动自己没有任何意义**
- 面试在短时间内无法试探你的全貌 → **包装的艺术**："确保简历上的每一句话都不会被问穿"
  - 第一层意思：知识储备足够扎实
  - 第二层意思：只要能圆回来就都是你的
- 没人在意你做没做这个项目，只要你了解项目细节、极端情况、为什么这样选型、有哪些数据支撑——能答上来，你就是做过
- 没人在意你懂不懂 Java 每个 API，只要你流畅回答问到的八股，你就是精通
- 这也解释了为什么很多认真学习很久的同学反而过不了面试
- 不是教"邪修抄近道"：要聪明地学、有所取舍地学、更高效地学

## 六、学习路线（完整版）

### 第一步：成为 AI 时代原住民（前置准备）

- [ ] 学会魔法上网，找到稳定好用的梯子
- [ ] 注册 GitHub（最前沿的项目 + 任何想找的资料）
- [ ] 配置 codex / claude code / chatgpt / gemini 并**深度使用**（极大提升学习效率）
- [ ] 学习如何高效 vibe / spec coding
- [ ] 建立信息收集渠道，拿第一手信息，打破信息差

### 第二步：选语言（Java vs Go）

- 后端只有 Java 和 Go 两种选择，别再纠结"Java 已死"
- **GO**：应对高并发的原生语言，大厂标配，高速扩张，八股只有 Java 的 1/5
- **JAVA**：中国存量最大的语言岗位，百搭，但八股繁多、竞争激烈、培训规模化

**为什么永远推荐先学 Java：**
1. 存量最大，80% 岗位还是 Java，有退路
2. Go 岗位接受 Java 转，Java 岗位不接受 Go 转 → Go 的路更窄，除非有把握一定能进大厂

### 第三步：技术栈

> 方法论：看网课效率极低，纸质笔记效率也低；**喜欢看文章和博客，然后和 AI 对话学习，逐步用 AI 澄清自己对知识的"幻觉"**。仍附上对应网课链接供选择。

#### 3.1 408 计算机四大件（数据结构、计算机网络、操作系统、组成原理）

- 无论什么方向都应掌握，是基本素养与后续基石
- 字节、腾讯非常爱考这部分来检查基础
- 四本书相当有难度，**不建议入门就啃**（会摧毁自信心）；建议至少学完语言基础语法再开始
- 学习技巧（"jia"）：遇到难懂的概念不要死磕细节，先站在更高视角理解它在这个情景/环节的作用，学得差不多（学完整个架构/整门课）再深入

#### 3.2 语言 -- JAVA、JUC、JVM

- JAVASE：Java 语法及常用 api
- JUC 并发编程：并发工具包
- JVM 虚拟机：Java 底层
- 本质是语言学，尽可能让自己处于环境中，理解什么情况下用什么而非单纯背诵
- 语言学习枯燥，深陷语言泥沼会打击积极性；JUC + JVM 是**八股重灾区，可后置学习**

#### 3.3 数据库 -- MySQL、Redis

- MySQL：存长期数据的硬盘数据库；Redis：跑在内存里的高速缓存数据库
- 重要性：very 重要，面试拷打重灾区
- 💡 **AI 时代 MySQL 可替换为 PostgreSQL**（原生支持向量数据、向量检索索引及丰富扩展生态，天平已倾斜）

#### 3.4 框架 -- JavaWeb、SpringBoot、Mybatis-Plus

- JavaWeb：最原始的网页接口底层技术，搞懂数据怎么在前后端流转
- SpringBoot：基于 Spring 的一站式框架，企业开发主流
- Mybatis-Plus：增强持久层框架，省去重复 SQL
- 面试考察相对少，可以速通，学会如何使用就好

#### 3.5 工程工具 -- Git、Linux、Docker

- Git：代码版本管理、分支合并、冲突处理；Linux：线上查日志、部署；Docker：统一运行环境
- 工作和开发的必要前提，**尤其是 git 和 linux 命令务必会使用**（不会可能闯大祸）
- 面试直接问的不多（默认你熟练），要动手实践

#### 3.6 中间件 -- Elasticsearch、RocketMQ

- ES：分布式检索中间件，擅长全文模糊搜索，辅助主库实现复杂查询
- RocketMQ：消息队列，异步消息完成解耦、削峰、异步通知，应对高并发神器
- 重要性高，面试拷打重灾区；RocketMQ 可替换为 Kafka、RabbitMQ，建议边做项目边学（项目用哪个学哪个）

#### 3.7 后端副本拓展 DLC（略显过时，想了解底层再学）

- 底层：JDBC、Maven、SSM 原生框架
- 微服务：Nginx、Nacos、SpringCloud
- 编程：设计模式、DDD
- 存储：Zookeeper、MongoDB、MinIO、向量数据库
- 框架：Dubbo、Netty、gRPC

### 第四步：算法

- 面试官会在面试开始/结尾出 1~2 道 mid/hard 算法题
- **核心代码模式**：不需要构造输入输出/导包/构造二叉树链表（LeetCode 默认）
- **ACM 模式**：需要自己构造输入验证输出，通常可以和面试官商量写死出入（直接用示例固定例子）
- 先建立认知：**看到一道新算法题写不出来是完全正常的**

**刷题节奏建议：**
- 把算法当成每天都要做的事情，留出一天上午专门做算法
- 一次性做几道到十几道，效果比一天一道两道好得多
- 越刷越熟练，看一眼题目就能默写；做一遍 hot100 可以在一天左右

### 第五步：项目

**项目是什么？** 有完整目标、自己动手做完、能落地、能写进简历的完整作品（图书管理系统这种课程作业不算亮点，太 low）

**关键认知：**
- 实现框架原有能力**不是亮点**，做出来完整系统**也不是亮点**，在此基础上的**优化才是亮点**
- 项目不等于技术栈堆叠（像报菜名一样全用上不高级）
- 举例（chunking 父子切分）：我为了解决什么痛难点？引入什么优化？为什么不用其他方案？优化前后数据怎么样？——**这种"优化叙事"才是项目亮点**
- 项目在面试中考察架构设计、问题处理、八股理解；面试基本不会单独拷打八股，而是结合项目场景问

**避坑：**
- ⚠️ 不要外卖和点评！一千份简历八百份外卖点评，怎么包装都看得出来
- 项目面试官不感兴趣 → 接受一小时八股拷打，甚至简历筛都过不了
- 黑马/尚硅谷这类教学项目很优秀，但**学完理解后建议换其他项目**放简历

**项目配置建议：** 一个传统后端项目 + 一个 AI agent 项目；有实习可只留一个项目，没实习至少两个

**什么时候开始做？** 两种思路：①学完语言开始，边做项目边学技术栈（用到什么学什么）；②学完技术栈再做（复习知识 + 新理解）

**去哪找项目？** ①竞赛项目（有技术亮点可讲）；②开源项目（GitHub / B站 / 小红书博主免费分享，质量参差需甄别）；③付费项目（知识星球/博主项目，付费降低撞脸率）

**什么是好项目（4 个角度）：**
1. **出发点**：围绕用户痛点，不是拿着锤子找钉子
2. **完整性**：核心功能完备 + 文档完备 + 测试用例覆盖大多数（70%）边界情况 + 压力测试
3. **闪光点**：解决业务难点的"优化叙事"（xxx 场景出现 xxx 问题 → 对比 xxx 方案 → 采用 xxx（为什么）→ 解决 xxx → 优化 xxx）
4. **可沉淀性**：能否把项目内容沉淀成一个个 SKILL

### 第六步：八股

- 是什么：面试官对技术栈的提问，因回答较为死板被戏称"八股"
- 八股也能看出你对技术的理解，灵活表达处可拉开差距；工作后也常用

**什么时候背？** 建议最后快要面试再背；更激进一点可以直接通过理解八股来学技术栈

**怎么背？** 理解为主、背诵为辅（"别真把计算机学成文科"）；多看面经观察高频考点，通过面试背八股；善用飞书记录思考

**去哪背？** 秉持拿来主义——能用别人整理好的就不自己整理；面试问到没见过的再单独整理
